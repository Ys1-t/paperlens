## 1. 项目定位

PaperLens 是一个面向学术论文的浏览器双语阅读扩展，目标是提供接近 Moonlight 的实时阅读体验：

- 左侧始终保留原始 PDF，由 PDF.js 按原版式渲染。
- 右侧按照真实阅读顺序显示结构化中文译文。
- 正文实时流式输出，不等待整篇论文处理完成。
- 公式、表格、图片和伪代码分别采用适合各自结构的处理方式。
- 用户可以接入自己的模型服务商，并在多套配置之间一键切换。

当前默认模式为“阅读模式”。它追求的是清晰、连续、快速的双语阅读，而不是在右侧像素级复制整张 PDF 页面。

## 2. 当前核心阅读体验

### 2.1 双栏对照阅读

- 左栏显示完整原始 PDF，包括字体、公式、图片、表格和页面排版。
- 右栏显示标题、正文、公式、表格说明、图片说明和 Algorithm 等结构化译文。
- 支持拖动中间分栏调整两侧宽度。
- 支持按页懒加载，优先处理当前可见页、相邻页和接下来的页面。
- 左右两栏滚动联动，程序主动定位时会临时关闭反向联动，防止跳转后又被拉回原位置。

### 2.2 实时流式翻译

- 译文以流式方式逐步显示，不需要等待整页完全翻译后再出现。
- 当前生产路径每页只发起一次视觉翻译请求；页面图像负责版面，PDF 原生文本只辅助漏段和不可变锚点核对。
- 普通页使用 1500px 页面图和 4096 输出上限；文字密集页才提高图像宽度或输出上限。
- 本地质量门拒绝残留英文、漏段、重复、拒答、损坏 LaTeX、算法缩进丢失、图表 token 缺失和 PDF 锚点缺失。
- 只有质量失败页才绕过坏缓存，以 temperature 0 和 2050px 页面图进行整页精修；正常页不增加额外模型轮次。
- 质量失败不会隐藏译文：当前结果立即显示并标记“译文可读 · 待精修”；后台重试期间保持可读，只有合格结果才替换。
- 摘要的 `(1)/(2)/(3)` 枚举不会被当成方程编号；真正的 Equation/Eq.、数学行末编号和 LaTeX tag 仍会核对，提示同时列出具体缺失项。

### 2.3 骨架、进度和错误反馈

- 译文尚未返回时显示阅读骨架，不用英文原文冒充中文译文。
- 页面状态区分为等待、翻译中、完成、部分待补全和失败。
- 顶部显示全文处理进度。
- 网络、授权、额度、超时和公式保护错误会转换成简短、可执行的中文提示。
- 技术诊断默认折叠，正常完成后自动弱化，不打断阅读。

## 3. 原文与译文双向对应

这是目前已经完成并验证的重要交互功能。

> 当前整页视觉路径没有段落 bbox，因此对应关系是可靠的**页级定位**，不是伪装成精确对应的段落定位。普通单击始终不会跳转。

### 3.1 从译文跳到原文

在右侧双击任意译文内容时，系统读取该译文所属页，左栏滚动到同一 PDF 页并短暂高亮页面。图片、表格定位入口和页码按钮也复用这套页级关系。

### 3.2 从原文跳到译文

在左侧 PDF 双击原文时，系统读取被双击的 PDF 页，右栏滚动到同一页译文并短暂高亮。它不会根据视觉模型猜测一个并不存在的段落 bbox。

历史 Typed Page IR 路径曾通过 `data-ir-id`、逐行 fragment 和旋转坐标换算实现节点级命中；由于该数据源已移除，这部分代码只作历史兼容，不写入当前能力承诺。

### 3.3 防误触设计

- 普通单击不会触发跳转，避免阅读和选词时频繁误触。
- 双击才执行原文 / 译文定位。
- 左侧双击只使用本次事件所属页，不会复用旧的文字 Selection 跳到另一页。
- 页级定位不会声称一个未经验证的段落或公式对应关系，避免“看似精确、实际错位”。
- 程序主动跳转时短暂抑制反向滚动联动，防止另一栏立即把页面拉回。

## 4. 公式处理

> 当前生产路径由整页视觉模型直接输出 LaTeX，前端统一经 KaTeX 安全门渲染；4.1–4.3 中“占位符 / sprite / Page IR”描述为历史结构化路径，不再由当前入口调用。

### 4.1 行内公式

- 行内公式继续以 LaTeX / KaTeX 形式显示在译文句子内部。
- 翻译模型只看到不可变公式占位符，不会直接改写显示用 LaTeX。
- 返回结果必须保持占位符数量、身份和顺序一致，否则只重试对应阅读单元。
- 对中文和行内公式的紧邻边界自动增加约 0.18em 的视觉间距。
- 中文后接公式、公式后接中文时会自动留白；逗号、分号等标点不会被错误推远。
- 流式译文更新和公式 OCR 重渲染后会重新计算边界间距。

### 4.2 显示公式

- 简单且可信的公式可直接由文本层恢复为 LaTeX。
- 复杂二维公式先保留原 PDF 紧致 crop，避免显示成被压平的伪公式。
- 同页复杂公式会拼成带稳定公式 ID 的 sprite，通常只进行一次视觉 OCR 请求。
- 视觉模型只负责转写公式为 LaTeX，不负责翻译正文。
- OCR 成功后，原位置替换为 KaTeX；OCR 失败时保留原公式 crop，不显示丑陋的扁平文本。
- 公式 OCR 使用独立的单并发通道，不阻塞正文翻译完成。

### 4.3 编号公式与二维结构恢复

历史 Page IR 路径不再单纯依赖 PyMuPDF 的原始文本块，而是使用“编号锚点 + 文本基线行带”恢复完整显示公式：

- 合并同一公式的分子、分母、根号、求和符号、上下限和主体。
- 吸收普通数学字体中的孤立数字，例如分式分子 `1`。
- 吸收 CMEX 伸缩括号，避免集合公式缺少右侧大括号。
- 吸收公式末尾逗号或句号，不让标点掉到下一行。
- 编号单独右对齐，但仍属于同一个显示公式节点。
- 使用文本基线区分相邻公式，避免高根号的 bbox 把下一条 `where ...` 定义吞进上一公式。
- 公式后的解释正文会继续保留为可翻译段落。

真实 D4L 回归已经覆盖：

- Simplex 集合公式右侧闭合括号。
- Equation (17)、(19)、(20) 的多行结构。
- Equation (24) 的分式碎片。
- Equation (29) 前不再出现孤立的 `1`。
- Equation (30) 的根式、分子、分母 `|Z|`、逗号和编号只生成一个公式块。
- Equation (30) 后的 `where d+...` 定义保持独立且完整。

### 4.4 LaTeX 安全与质量门

- KaTeX 所有入口统一经过数学字符规范化和全局防火墙。
- PDF / OCR 中的 Unicode 数学字母和运算符会转换为兼容的 LaTeX。
- 未知字符、替换字符、孤立 surrogate 和明显损坏的数学输入会直接回退。
- KaTeX 使用 `strict: ignore` 消除非致命 Unicode 警告，但真正的解析错误仍会触发回退。
- 质量门会拒绝连续双下标、连续双上标、范数不配对、平方后缀丢失、求和项缺失以及可渲染但语义明显错误的伪 LaTeX。
- 批量 OCR 中只有失败公式会进行一次单图复核，其他成功公式不重复请求。

## 5. 表格处理

> 当前阅读模式不在译文栏重建表格主体。视觉模型输出 `@@TABLE@@` 定位 token 和可见表注，前端替换为“查看左侧原表”；5.1–5.2 的 HTML table 重建规则是历史不可达路径。

### 5.1 语义表格重建

可信表格会在译文栏重建为真实 HTML table，而不是简单复制整张截图。

当前有两种可信来源：

1. 可选 PyMuPDF Layout 返回的高置信表格网格。
2. 基础 PyMuPDF 模式恢复的严格三线科研表，provenance 为 `pymupdf-ruled-text`。

基础模式的严格表格路径需要同时满足：

- 附近存在 TABLE caption。
- 至少三条宽度一致的水平规则线。
- PyMuPDF 的文字和严格线检测结果一致。
- 表格为简单窄表，当前限制为 2 至 4 列。
- 单元格结构完整且总量不超过 512。
- 第一列是短标签，后续列绝大部分为数值或科学计数结果。
- 不把 Algorithm、正文网格或复杂宽结果表误当成简单表格。

### 5.2 表格翻译规则

- 自然语言表题、表头和行标签可以翻译。
- 单表最多翻译 96 个文字标签，控制请求规模。
- 数值、标准差、科学计数法、URL、公式和 LaTeX 片段保持原样。
- NSGA-II、HV、DTLZ1 等方法名、指标和数据集缩写保持原样。
- 表头使用 `th` 和 `scope="col"`，行标题使用 `scope="row"`，保留读屏语义。
- 表格支持横向滚动、固定表头、固定首列、数值对齐和公式单元格 KaTeX。
- 表题和表下注释按照论文阅读习惯居中显示。

### 5.3 安全回退

- 低置信表格、超大表格、复杂宽表和无法证明结构的表格不会强行生成 HTML。
- 这些表格保留原表 crop 或“查看左侧原表”的定位入口。
- 即使回退，也会保留并翻译表题和说明。
- 普通复杂表格不会因为新三线表检测而丢失原有行数或多行表头。

真实 D4L 回归包括：

- Table I 恢复为 14 行 × 3 列。
- Table II 恢复为 16 行 × 3 列。
- 表格 bbox 不再吞入左栏残字或下方正文。
- 后续 7 列复杂结果表仍保持原有 30 行完整结构。

## 6. 图片与图注

- 左侧 PDF 始终是图片的视觉真相。
- 普通图片不再复制到右侧译文栏，避免重复图片打断阅读节奏。
- 视觉模型在图形原位置输出 `@@FIGURE@@`，右栏替换为“查看左侧原图”，随后显示翻译后的可见 figure caption。
- 译文输出 Markdown 图片或 img 标签会被质量门拒绝；图像像素不会进入译文正文。
- PDF 原生文本出现明确 Figure / Fig. caption、但译文缺少定位 token 时，会触发高精度重试。
- 当前视觉路径的双击定位粒度为同页；历史 Page IR 路径的 figure bbox 高亮不再属于生产入口。

## 7. Algorithm 与伪代码

- 整页视觉模型根据页面像素识别 Algorithm，输出 Markdown 标题和完整的 `algorithm` 围栏。
- 每条逻辑行必须独占一行并保留行号；If / For / While 等嵌套内容每级缩进 2 个空格。
- 注释和自然语言关键字翻译为目标语言，变量、运算符和行内 LaTeX 保持原样。
- 本地质量门检查围栏是否闭合、是否至少保留两条编号行及一个嵌套缩进行；不合格时定向精修整页。
- 前端对 Algorithm 使用等宽行号列、可换行内容列和适合长伪代码的行距，避免文字重叠。

## 8. PDF 打开方式

- 扩展不再自动接管所有 PDF 链接。
- 浏览器仍可正常打开、登录访问或下载 PDF。
- 用户主动点击扩展弹窗、右键菜单、粘贴 URL 或选择本地文件时，才进入 PaperLens 阅读器。
- 支持在线 PDF、本地 PDF、拖放文件和粘贴链接。
- 这保证了需要登录、验证码或手动下载的论文站点仍可以先使用浏览器原生流程。
- 扩展升级时会清理旧的 PDF 自动重定向规则，避免旧行为复活。

## 9. 科研助手与证据工作台

- 深读模式在本地对 PDF 原文、译文和科研笔记建立混合中英文检索索引，不额外消耗一次“检索模型”请求。
- 回答后核验“第 N 页”引用是否超出文档或是否真的查阅，并显示 0–100 的证据支持度；该分数只表示可追溯性，不表示答案必然正确。
- “查看 N 条证据”可展开 E1/E2 片段，显示 PDF 原文 / 译文、章节线索、邻页关系，并可直接跳回 PDF 页核对。
- 上一轮实际证据可用于理解追问；助手旧结论本身不会被当成论文证据。
- 历史会话持久化有限的证据片段、工具轨迹和支持度，恢复后仍可展开。
- 常用科研技能直接显示；Ctrl+K 可按名称或用途搜索全部 15 个技能，支持方向键、Enter、Escape 和焦点恢复。
- 回答可收入科研笔记，也可导出带证据溯源的 Markdown 或 PDF；笔记支持复制、下载和同步 Obsidian。

## 10. 多模型服务商与 Profile

- 支持 DeepSeek 官方 API。
- 支持 OpenAI 官方 API。
- 支持 Gemini 官方原生协议。
- 支持 OpenAI 兼容中转站，可自定义 Base URL 和模型名。
- 可以保存多套 Provider Profile，每套包含名称、协议、Base URL、API Key 和模型。
- 可在阅读器、扩展弹窗和设置页一键切换活动 Profile。
- 支持新增、编辑、复制、重命名、删除和激活 Profile。
- 删除当前 Profile 后会自动选择剩余的有效 Profile；最后一套 Profile 受到保护。
- API Key 在公开配置和诊断信息中只显示脱敏后缀。
- 测试连接使用临时覆盖值，不会意外持久化未保存配置。
- Base URL 会检查协议、嵌入式凭据和疑似 API Key 查询参数，降低误配置和泄密风险。

## 11. 翻译稳定性、缓存与恢复

### 11.1 稳定节点协议（历史不可达）

- Typed 主路径使用稳定节点 ID 的 NDJSON，而不是依赖返回位置猜测对应关系。
- 流式返回的每个完整节点可以独立落地。
- 缺失节点、空译文、未翻译英文和公式占位符损坏都不会写入缓存。
- 单个节点失败只恢复该节点，不影响同页已经成功的内容。
- 数学占位符失败时，只重译公式之间的 prose slots，再由本地按原 ID 和顺序拼回公式；该类请求携带可选 `nodeSlotRetry` 标志，改用专用 system prompt（相邻片段按 id 顺序回插、与两侧公式自然衔接、保持同一句式与指代）。
- 节点翻译 prompt 内置学术语体、批内术语一致（优先领域通行中文译名）、歧义术语首现括注英文与明确不译清单（方法/系统名、数据集名、变量名、缩写、引用标记、URL、数字）。
- 用户自定义 systemPrompt 在节点协议下以追加方式生效（拼接在内置 prompt 之后），不再被忽略。

### 11.2 缓存

- 译文存储在浏览器 IndexedDB。
- 缓存身份包含模型配置、Base URL 和翻译管线版本。
- API Key 和 Profile 显示名称不进入缓存身份。
- 空响应、损坏响应和未通过质量门的结果不会缓存。
- 公式 OCR 使用独立版本化缓存命名空间。

### 11.3 调度和取消

- 当前页优先于预取页。
- 可见页、相邻页和后续页按优先级调度。
- 同一页面任务去重，手动重试时会取消旧 generation。
- 排队、网络读取、局部恢复和公式 OCR 均支持取消。
- 瞬时网络失败在尚未输出内容时自动重试一次；已经开始流式输出后不会整次重放。
- 排队等待不会被错误计算为模型响应超时：排队期间无活动守卫停表（带 450 秒兜底上限，端口消息丢失时页面不会永远显示排队中）。
- 首字节到达前守卫保持完整 90 秒首字节窗口；连接中与推理模型思考期的心跳只证明请求活着，不会把窗口压成 45 秒空闲窗口。
- 推理模型长思考期约每 15 秒收到一次 thinking 心跳状态，正常思考不会被误判为无响应。
- 正文请求排队死线为 240 秒（等完一个完整慢请求周期），排队超时与模型响应超时使用可区分的错误文案。

## 12. 当前版面分析与视觉模型分工

1. PDF.js 在浏览器内渲染完整页面图，页面图是栏结构、阅读顺序、公式、图表和 Algorithm 的版面权威。
2. PDF.js 原生文本随同同一次请求作为辅助信号，只用于检查漏段、辨认小字和核对引用 / 方程编号 / 数值 / 数据集等锚点；不把它的空格或扁平顺序当作版面证据。
3. 视觉模型返回 Markdown、LaTeX、Algorithm 围栏以及 `@@FIGURE@@` / `@@TABLE@@` 定位 token。
4. 本地质量门不调用模型，先判断结构与锚点是否合格；失败才进入新的高精度整页请求。
5. 页面图和原生文本均视为不可信论文数据，不会执行论文中夹带的指令或提示词。

## 13. 浏览器内会话与性能

- 不上传整份 PDF 到 PaperLens 自建服务；每个需要翻译的页面图只发给用户选择的模型供应商。
- 当前页面和相邻页面优先调度，避免打开长论文时串行等待所有页面。
- IndexedDB 缓存通过质量门的译文；缓存身份包含模型、Base URL 和 `vision-page-v12` 管线版本。
- 普通页保持 1500px / 4096 输出预算，密集页自适应提高，只有质量失败页使用 2050px。
- PDF.js 中间 Canvas 和所有需要频繁读取像素的 viewer Canvas 均启用 `willReadFrequently: true`。
- 已消除 `genericComposeSMask` 场景反复出现的 Canvas2D `getImageData` 性能警告。

## 14. 划词、原文对照和辅助阅读

### 14.1 划词即时翻译（v0.8.22 起可用）

- 在左栏 PDF 的文字层拖选文字，松开鼠标后即在选区附近弹出翻译浮层。
- 浮层先显示原文片段和「翻译中…」，译文流式就地更新；推理模型思考期显示「思考中…」。
- 划词请求走 priority 免排队通道（不与正文翻译抢并发槽位），并自动附带选区两侧的相邻原文作为语境（每侧约 480 字符），译文只包含所选片段。
- 划词请求不读也不写共享译文缓存，不会污染正文翻译缓存。
- 浮层优先显示在选区上方且向上生长，不遮挡选区；上方空间不足时显示在下方；超长译文在浮层内滚动。
- 浮层内容可以用鼠标选中复制。
- 点浮层外任意处、按 Esc 或左栏滚动超过阈值会关闭浮层并取消未完成请求；再次选择新文本会先取消旧请求再发起新请求。
- 与双击定位互不干扰：双击 / 三击选词只触发双向定位跳转，拖选才触发划词浮层；单击不触发任何跳转。
- 设置页提供「划词即时翻译」开关（默认开启）；关闭后完全不监听划词事件，保存后即时生效。

### 14.2 原文对照（bilingual）

- 设置页勾选「原文对照」后，结构化译文的段落、标题、普通文本和说明文字下方以灰色小字保留对应英文原文。
- 原文来自本地渲染层已有的源文本，不产生任何额外模型请求。
- 公式、表格、图片引用和伪代码不加原文行，保持结构阅读的密度。
- 原文行只在该块译文全部落地后出现；流式更新与局部重试不会让原文行闪烁或重复；仍在骨架（partial）或失败状态的节点不显示原文行。
- 开关保存后即时生效，包括已经打开的阅读器页面（关闭同理）。

### 14.3 其他辅助阅读

- 文本、公式、表格和图片引用均可使用键盘焦点和双击定位。
- 支持 reduced-motion：划词浮层与原文行在该模式下无动画。
- 译文排版提高了字号、行距、阅读留白和操作控件尺寸。

## 15. 诊断与隐私

### 15.1 本地诊断

- viewer 和 Service Worker 会捕获 error、unhandledrejection、console warning / error 和 Port 断开原因。
- 扩展弹窗可以打开独立诊断页。
- 诊断页支持刷新、复制和清空记录。
- 即使 Service Worker 异常，已写入本地存储的诊断仍可读取。
- 日志会清理 Bearer Token、API Key、URL userinfo 和敏感查询参数。

### 15.2 隐私边界

- API Key 只保存在浏览器本地 `chrome.storage.local`。
- v0.9.6 起翻译按页把渲染位图发送给用户自选的视觉模型接口；无任何本地/自建服务参与。
- 除用户选择的模型接口外，项目不会主动把论文或凭据发送给其他第三方。

## 18. 当前仍保留的边界

- 右栏是结构化阅读排版，不是像素级翻译 PDF。
- 没有 caption 的非常规图片、极端跨页表、旋转表、复杂嵌套矩阵和跨栏公式仍可能回退到左侧原图或原表。
- 复杂公式最终质量仍受到视觉模型能力影响；本地门能拒绝结构损坏，但不能证明每个数学符号语义都正确。
- 扫描 PDF 需要整页视觉 OCR，速度和成本会高于带文字层的普通论文。
- 历史 PyMuPDF Layout 管线受 PolyForm Noncommercial / Artifex 商业双许可证约束；生产入口已移除，不应重新默认启用。
- Chrome / Edge 加载解压扩展后，代码更新需要在扩展管理页点击“重新加载”，并刷新已经打开的旧阅读器标签页。

## 19. 最常用操作速查

### 打开论文

1. 正常打开或下载 PDF。
2. 点击 PaperLens 扩展图标。
3. 选择翻译当前 PDF、粘贴链接或打开本地 PDF。

### 查看原译文对应关系

- 双击右侧译文：跳到并高亮左侧原文。
- 双击左侧原文：跳到并高亮右侧对应译文。
- 单击：不跳转，可正常阅读和选词。

### 切换模型服务商

1. 在设置页保存多套 Provider Profile。
2. 在阅读器或扩展弹窗选择目标 Profile。
3. 新请求立即使用新 Profile，旧请求保持自己的配置快照。

### 更新代码后生效

1. 在 `edge://extensions` 或 `chrome://extensions` 找到 PaperLens。
2. 点击“重新加载”，确认卡片版本为 1.2.6。
3. 刷新旧的 PDF 阅读器标签页。
